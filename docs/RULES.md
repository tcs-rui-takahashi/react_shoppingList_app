# 運用ルール（RULES）

## PR 運用方針

**内容・方針**

- 変更概要・目的・テスト内容を明記し、品質担保のためのチェック項目（動作確認・テスト・型定義など）は PR テンプレートに準拠する。

## 型運用

**内容・方針**

- 型定義は一括管理し、共通モジュールで扱う。
- 新規型追加時は既存との重複を避ける。

**背景・理由**

- 設計段階で型を共有し、後続機能の拡張を容易にする。

---

## ディレクトリ構成

**内容・方針**

- `apps/` と `tests/` の構造は一致させる。
  - 現状のファイル構造を参照
- `hooks/` や `utils/` などの共通フォルダは `apps/` 配下に配置する。

**背景・理由**

- 構造の統一により、テストコードとの対応関係が明確になる。
- ディレクトリ階層を明確化し、保守性を高める。

---

## 命名ルール

**内容・方針**

- 型ファイルとロジックファイルを分離する。
  - 型定義：`*.type.ts`
  - ガード・判定ロジック：`*.guard.ts`

**背景・理由**

- 型とロジックの責務分離により、カバレッジ精度と保守性を向上させる。
  - 型定義ファイルはテスト対象外に設定しており、もしロジックを書いてしまうとカバレッジが不正確（低く）表示されてしまう。
